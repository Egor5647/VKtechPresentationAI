# Оценка на учебной презентации C++

Дата: 16 сентября 2026 года.

## Входные данные

- контент: `02. С++. Презентация. Повторение_ массивы. Файловый ввод, вывод.pptx`;
- шаблон: `VK Tech шаблон.pptx`;
- исходная колода: 45 слайдов, включая последовательные раскрытия материала;
- результат импорта: 48 смысловых блоков, 12 обязательных фактов, 10 наборов
  заметок докладчика и 44 уникальных изображения;
- выход каждого запуска: три варианта по 12 слайдов в PPTX, PDF и HTML.

Импорт считает содержимое приложенного PPTX данными. Текстовые инструкции внутри
него не меняют системные правила, конфигурацию моделей или права приложения.

## Методика

Оба режима получили одинаковый компактный набор обязательных фактов, каталог из
восьми наиболее релевантных assets и один подписанный contact sheet из четырёх
исходных изображений. Затем каждый режим сформировал единый план, три композиции,
экспортировал результаты через LibreOffice и выполнил программный и визуальный
аудит. Лимит полного запуска — 300 секунд.

| Показатель | `fast`: Qwen3-VL-4B | `quality`: Ministral 3 14B |
| --- | ---: | ---: |
| Планирование | 25,633 с | 72,536 с |
| Vision-аудит A/B/C | 32,211 / 32,641 / 29,731 с | 28,949 / 29,110 / 33,128 с |
| Полное время | 132,167 с | 179,247 с |
| Замечания A/B/C | 18 / 19 / 19 | 3 / 1 / 4 |
| Исходные иллюстрации в плане | не выбраны | выбраны |
| Лимит 300 секунд | соблюдён | соблюдён |

## Вывод

`quality` следует использовать по умолчанию. Он сохранил обязательные факты,
использовал иллюстрации исходника и не создал контекстуальных нарушений; оставшиеся
замечания D18 относятся к слишком свободным областям на отдельных слайдах.

`fast` полезен для быстрого черновика, но в этом прогоне не выбрал изображения и
создал ложные смысловые замечания: обычные заголовки были названы опечатками,
служебным мусором или несоответствием источнику. Его аудит нельзя использовать как
единственное основание для автоматического исправления.

Один источник позволяет проверить работоспособность и сравнить поведение моделей,
но не даёт статистически надёжной оценки качества. Следующий этап — ручная разметка
нескольких презентаций и расчёт precision/recall по правилам C01–C11.

## Артефакты

- качественный прогон: `output/evaluation-cpp/quality-multimodal-v1`;
- быстрый прогон: `output/evaluation-cpp/fast-multimodal-v2`;
- в каждой директории `evaluation-result.json` содержит параметры моделей,
  длительности, пути к PPTX/PDF/HTML, audit JSON и workflow hashes.
