# VK Tech Presentation AI

Сервис принимает неизвестный PPTX-шаблон и контент-пакет, формирует единый план
содержания, создаёт три кандидата для каждого слайда и автоматически собирает из
них одну презентацию. В редакторе можно сравнить кандидатов по миниатюрам, выбрать
другую компоновку или перегенерировать отдельный слайд. Выбор компоновки обновляет
превью сразу; PPTX, PDF и HTML пересобираются один раз при скачивании. Скачивается
одна актуальная версия презентации.

Три варианта различаются по информационной плотности. `Крупно и кратко` использует
крупный кегль и минимум объектов, `Сбалансированно` добавляет опорные блоки,
`Подробно` показывает до трёх деталей более компактным кеглем. Это реализует
свободно выбираемую ось различий из ТЗ через плотность контента и композицию.
Модель формулирует три самостоятельные законченные версии одной мысли: короткую,
сбалансированную и подробную. Сервис не обрезает текст по числу символов и не
добавляет многоточие. Планировщик очищает служебные заголовки источника, закрепляет
за каждым слайдом отличительные термины и отклоняет изменение чисел, границ и
направления оптимизации. Для нативных схем отдельно создаются 2–3 короткие подписи.

## Текущее состояние

Работает полный программный путь: безопасный импорт PPTX, Design IR и Content IR,
планирование в переключаемом режиме `quality`/`fast`, классификация и структурирование
слайдов, три внутренние Scene IR, автоматическая оценка и сборка выбранной Scene IR,
нативные текст, таблицы, графики и редактируемые схемы из фигур, экспорты, превью,
детерминированный и контекстуальный аудит, покадровый выбор и перегенерация.
Планировщик автоматически выбирает, где нужна генерируемая иллюстрация, где лучше
редактируемая схема, диаграмма или таблица, а где визуал не добавляет смысла.
Редактор палитры в левой панели даёт живой предпросмотр и пересобирает все форматы
в выбранной гамме без повторного вызова текстовой модели. Внешний инференс не заменяется тестовыми ответами:
без настроенного endpoint задача переходит в `awaiting_input`.

Контрольный прогон с синтетическим планом создаёт внутренние кандидаты и одну итоговую
колоду на каждом из трёх шаблонов.
Дополнительно выполнен сквозной прогон на предоставленной учебной презентации:
импортированы текст, заметки докладчика и встроенные изображения, после чего обе
локальные модели построили по три варианта на 12 слайдов. Подробности и ссылки на
артефакты приведены в [EVALUATION_CPP.md](EVALUATION_CPP.md).

## Быстрый запуск

Основной локальный сценарий рассчитан на Mac с Apple Silicon. Понадобятся Homebrew
и не менее 20 GB свободного места. Веса моделей хранятся в кэше Hugging Face и
никогда не добавляются в Git.

```bash
make setup
make download-qwen
make download-ministral
make download-zimage
make run
```

`make run` одной командой запускает выбранную текстовую модель, Z-Image, API,
worker и собранный веб-интерфейс, после чего открывает `http://127.0.0.1:8000`.
По умолчанию используется качественный режим Ministral. Быстрый режим запускается
так:

```bash
MODEL_MODE=fast make run
```

Логи всех процессов находятся в `.local/logs`. Для остановки нажмите `Ctrl+C` в
терминале с `make run`. Настройки можно изменить в `.env`, который создаётся из
`.env.example` командой `make setup`.

Контейнерный запуск приложения без локальных весов также поддерживается. Сначала
укажите внешние model endpoints в `.env`, затем выполните:

```bash
docker compose up --build
```

`make setup` устанавливает через Homebrew Python, Node.js, pnpm, Poppler и
LibreOffice, если их ещё нет. Пути к `soffice` и `pdftoppm` можно переопределить
переменными `SOFFICE` и `PDFTOPPM`. `FONT_DIRS` содержит разделённые системным
символом пути к доступным TTF/OTF для точной проверки переноса текста.

## Настройка моделей

На Apple Silicon режим отбора (`MODEL_PROFILE=selection`) использует локальный
OpenAI-совместимый сервер MLX-VLM. `quality` выбран по умолчанию; смена режима
требует перезапуска model server и того же значения `MODEL_MODE` у worker:

```dotenv
MODEL_BASE_URL=http://127.0.0.1:8001/v1
MODEL_API_KEY=
MODEL_MODE=quality
MODEL_NAME=
MODEL_TIMEOUT_SECONDS=300
```

| Режим | Модель | Локальные веса | Полный прогон |
| --- | --- | --- | --- |
| `quality` | Ministral 3 14B Instruct 4-bit | около 8,42 GB | 179,247 с |
| `fast` | Qwen3-VL-4B Instruct 4-bit | около 3,09 GB | 132,167 с |

Оба замера включают один и тот же реальный PPTX, четыре визуальных примера для
планировщика, три варианта по 12 слайдов, PPTX/PDF/HTML и vision-аудит. На этом
материале `quality` использовал исходные изображения и дал 1–4 детерминированных
предупреждения; `fast` не выбрал изображения и дал 18–19 замечаний, включая ложные
контекстуальные срабатывания. Для статистической оценки всё ещё нужен размеченный
набор из нескольких презентаций.

Финальный режим (`MODEL_PROFILE=final`) требует предоставленный VK endpoint и
доступный на нём model ID. После получения доступа этот ID добавляется в список
разрешённых aliases в `config/models.yaml` и проверяется отдельным прогоном:

```dotenv
VK_BASE_URL=https://vk.example/v1
VK_API_KEY=...
VK_MODEL_NAME=<approved-vk-model-id>
```

Ключи хранятся только в `.env`, файл исключён из Git. Если протокол VK отличается
от OpenAI Chat Completions с `json_schema`, потребуется отдельный транспорт в
`model.py`.

Для генерации изображения задаются `T2I_BASE_URL` и `T2I_API_KEY`. Endpoint должен
возвращать base64 PNG/JPEG/WebP от модели Z-Image-Turbo. На Apple Silicon доступен
локальный OpenAI-совместимый адаптер к 8-битной MLX-квантизации той же модели:

```bash
./scripts/install_zimage.sh
T2I_PORT=8002 ./scripts/start_zimage_server.sh
export T2I_BASE_URL=http://127.0.0.1:8002/v1
```

Первый запрос загружает веса `mzbac/Z-Image-Turbo-8bit`; последующие используют
кэш Hugging Face. Адаптер выполняет запросы последовательно, ограничивает размер
изображения и запускает Turbo с 9 шагами и guidance 0. Число иллюстраций
определяется содержанием: для каждого слайда сохраняются стратегия, уверенность и
причина выбора. Ограничение в восемь изображений остаётся техническим
предохранителем для одного задания. Планировщик никогда не
использует сгенерированное изображение как источник фактов.

## Формат контента

Поддерживаются PPTX, PDF, UTF-8 TXT/Markdown, CSV и JSON `ContentIR`. Импорт PPTX
группирует текст по исходным слайдам, отдельно сохраняет заметки докладчика и
автоматически регистрирует встроенные PNG/JPEG/WebP как assets. Вопросы,
разделители и слайды без извлекаемого текста остаются необязательными источниками,
чтобы их можно было сократить без потери фактов. До четырёх наиболее значимых
изображений передаются мультимодальному планировщику; лимит задаёт
`MODEL_MAX_SOURCE_IMAGES`. Полный Content IR остаётся в задании и отчёте, а в
контекст планирования передаются обязательные факты и компактный каталог assets;
его размер задаёт `MODEL_MAX_PLANNING_ASSETS`. PDF импортируется смысловыми
фрагментами примерно по 500–1200 символов с точной ссылкой на страницу и номер
фрагмента; наиболее близкие к брифу блоки выбираются в
ограниченный контекст планировщика. Лимиты задают `MODEL_MAX_PLANNING_CLAIMS` и
`MODEL_MAX_PLANNING_CHARS`. Презентации длиннее 12 слайдов планируются связанными
блоками максимум по шесть слайдов. Каждому слайду заранее назначается отдельный
диапазон исходных фактов; повтор заголовка или главной мысли отклоняется до верстки.
CSV должен иметь категории в первом столбце,
названия рядов в первой строке и числовые значения в остальных ячейках. Для
отсутствующего корпоративного шрифта генератор использует `FONT_FALLBACK`
(по умолчанию Arial) и проверяет размеры текста по установленному файлу шрифта.
Для сложного пакета используйте JSON по схеме `/openapi.json`; `source` обязателен для
каждого факта и набора данных. Изображения сначала загружаются через `/api/assets`,
после чего возвращённый относительный `path` можно указать в `ContentIR.assets`.
Для изображений внутри PPTX этот шаг выполняется автоматически.

Реальный приёмочный прогон PPTX-контента запускается так:

```bash
MODEL_MODE=quality .venv/bin/python scripts/evaluate_pptx.py content.pptx template.pptx --output output/evaluation-quality
```

## Проверки

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/verify_templates.py /path/to/templates --output output/smoke
cd frontend && pnpm run build
```

`verify_templates.py` использует подписанный синтетический fixture и не вызывает
модель. Он проверяет девять PPTX, PDF, HTML, Scene IR и отчётов аудита. PostgreSQL
проверяется при наличии `TEST_DATABASE_URL`. Результаты smoke-прогона исключены
из Git.

## Ограничения

- Серверный рендер LibreOffice может отличаться от PowerPoint при отсутствии
  корпоративных шрифтов. В предоставленных материалах отдельных файлов шрифтов
  нет: используются системные шрифты и настройки PPTX, а аудит возвращает
  `unknown` при невозможности подтвердить метрики.
- Контекстуальный аудит зависит от vision-возможностей выбранной модели. На
  проверенной презентации Qwen дал ложные срабатывания, поэтому основным режимом
  выбран Ministral.
- Схемы состоят из обычных редактируемых фигур PowerPoint. Это даёт одинаковый
  размер карточек и текста в PowerPoint и LibreOffice.
- Поддержка шаблонов PDF и изображений остаётся расширением. Основной адаптер — PPTX.
- Публичный доступ требует внешней аутентификации, TLS, антивирусной проверки и
  объектного хранилища; текущая конфигурация слушает только localhost.
