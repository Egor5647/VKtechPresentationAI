# Модели и API

Текущий провайдер — [Polza.ai](https://polza.ai/docs/glavnoe/quickstart).
Конфигурация API-моделей находится в `config/models.yaml`, секреты — в
локальном `.env` или переменных окружения. `.env` исключён из Git.

| Роль | Модель | API |
| --- | --- | --- |
| Планирование, перегенерация, vision-аудит, отбор иллюстраций | `qwen/qwen3.8-27b` | `POST /api/v1/chat/completions` |
| Генерация иллюстраций | `tongyi-mai/z-image` | `POST /api/v1/media`, затем `GET /api/v1/media/{id}` |

Точный ID Qwen подтверждён живым каталогом Polza 25 сентября 2026 года.
Каталог указывает поддержку изображений, `response_format` и
`structured_outputs`. На этой модели проверены реальные текстовые и
мультимодальные запросы; локальные MLX-серверы не участвуют.

## Конфигурация

```dotenv
POLZA_API_KEY=<ваш-ключ>
MODEL_BASE_URL=https://polza.ai/api/v1
MODEL_NAME=qwen/qwen3.8-27b
MODEL_RESPONSE_FORMAT=json_object
MODEL_TIMEOUT_SECONDS=300
MODEL_REASONING_ENABLED=0
MODEL_TRUST_ENV=0
MODEL_MAX_TOKENS_PLANNING=6500
MODEL_MAX_TOKENS_REGENERATE_SLIDE=3000
MODEL_MAX_TOKENS_VISION_AUDIT=3000
MODEL_MAX_TOKENS_IMAGE_SELECTION=3000
MODEL_CACHE=1
T2I_BASE_URL=https://polza.ai/api/v1
T2I_MODEL=tongyi-mai/z-image
T2I_ASPECT_RATIO=16:9
T2I_TIMEOUT_SECONDS=180
```

Полный образец — `.env.example`. `MODEL_API_KEY` и `T2I_API_KEY` позволяют
явно переопределить ключ для соответствующего endpoint. Общий ключ Polza
автоматически используется только на HTTPS-адресе `polza.ai`.
Короткое имя `qwen3.8-27b` нормализуется в полный ID.
`MODEL_NAME` проверяется по манифесту; автоматической смены модели нет.

Загрузка `.env` выполняется при чтении настроек приложения. Переменные
окружения не перезаписываются. Для системного HTTP(S)-прокси задайте
`MODEL_TRUST_ENV=1` и совместимые с HTTPX переменные прокси.
Пустой `T2I_BASE_URL=` отключает генерацию иллюстраций.

Старые `MODEL_PROFILE`, `MODEL_MODE`, `VK_*` и параметры локальных
MLX-процессов удалены из рабочего сценария. Для миграции старого `.env`
замените локальные endpoint и MLX ID на значения выше. Веса, сведения о
квантизации и ограничения локальной памяти больше не определяют выбор API-модели.

## Контракты и ошибки

- По умолчанию используется `response_format: {"type":"json_object"}`,
  полная JSON Schema передаётся в системной инструкции. Ответ обязательно
  проверяется Pydantic и затем предметными проверками планировщика.
  После невалидного JSON есть одна корректирующая попытка: модель получает
  точные пути полей, типы ошибок и сообщения валидатора с допустимыми значениями.
  Невалидный ответ не принимается и не попадает в кэш.
- `MODEL_RESPONSE_FORMAT=json_schema` явно включает `strict=true` в API.
  Несмотря на заявленную поддержку structured outputs в каталоге, при живой
  проверке полной вложенной схемы PresentationPlan этот режим исчерпал лимит
  6500 выходных токенов. JSON-режим с той же схемой в инструкции успешно
  вернул валидный план; поэтому он выбран по умолчанию. Автоматического
  переключения режима или модели нет.
- Изображения передаются как `image_url` с data URL. API-ключ хранится в
  Authorization и не включается в манифесты, кэш или ответы health endpoint.
- Reasoning по умолчанию отключён; его можно включить явно.
- HTTP 429 и временные серверные ошибки текстового API повторяются до трёх
  попыток с ограниченной задержкой. Неоднозначный сетевой таймаут и создание
  задания изображения автоматически не повторяются, чтобы не дублировать оплату.
- HTTP 401/402/403/404, исчерпанные сетевые попытки и обрезанный ответ сообщаются
  через `ModelUnavailable`; worker переводит задание в `awaiting_input`.
- В манифесте сохраняются модель, роль, время, статус и доступные usage/cost поля.
  Тела ошибок провайдера и ключи туда не попадают.
- В логах и метаданных вызовов ошибки структуры содержат только безопасные
  пути полей и типы ошибок — без текста ответа. После двух неудачных попыток
  worker переводит задание в `awaiting_input` с указанием проблемных полей;
  в UI можно повторить генерацию.
- Кэш учитывает endpoint, модель, параметры генерации, промпт, схему и входные
  изображения. Готовый кэш не заменяет отсутствие настроенного API-ключа.

## Генерация иллюстраций

Polza Z-Image принимает промпт до 1000 символов и поддерживаемое соотношение
сторон (по умолчанию 16:9). Worker создаёт асинхронное задание, ожидает результат
в пределах `T2I_TIMEOUT_SECONDS` и сохраняет изображение как PNG.
Скачивание из хранилища Polza не передаёт ключ API.

Схемы, таблицы и графики по-прежнему создаются программно и остаются
редактируемыми. Сгенерированная иллюстрация не является источником фактов.
Для отдельного T2I API сохранён путь `/images/generations` с base64-ответом.

## Проверка

```bash
make test
make check-api
.venv/bin/python scripts/check_api.py --image
.venv/bin/python scripts/check_api.py --pipeline
```

`check-api` использует небольшой синтетический пример и простую JSON-схему,
проверяя транспорт для всех четырёх ролей. Это не оценка качества полного
планировщика. Опция `--image` дополнительно создаёт одну иллюстрацию.
Опция `--pipeline` проверяет рабочие контракты планирования, vision-аудита,
перегенерации и отбора изображений, а также собирает синтетическую презентацию
из трёх слайдов во всех форматах. Нужны LibreOffice и Poppler.
Эти команды расходуют баланс API; обычные автотесты работают без внешних вызовов.

Сквозная проверка объединённого конвейера 28 сентября 2026 года завершилась успешно: планирование,
vision-аудит, три варианта трёхслайдовой презентации и экспорты PPTX/PDF/HTML
заняли 41,6 с на синтетических данных. Отдельно прошли рабочие контракты
перегенерации слайда и отбора изображений, а также генерация и скачивание
иллюстрации Z-Image 1280×720. Все реальные ответы прошли локальную валидацию
с первой попытки. Это проверка интеграции, не бенчмарк качества модели.

Отчёты `MODEL_BENCHMARK.md`, `EVALUATION_CPP.md` и
`docs/PERFORMANCE_COLD_RUN_2026-09-17.md` относятся к прежним MLX-моделям.
Их скорость и качество не являются измерениями текущей API-конфигурации.
